## Main subsystems

1. **Authenticated web shell and account handoff.** `main/preload.ts:26-33` injects build-time API, web, WebSocket and docs base URLs. `main/index.ts:1257-1276` restores auth and passes `VITE_API_BASE_URL`, `VITE_WS_BASE_URL` and `VITE_WEB_BASE_URL` into the app. Auth code exchange is `main/utils/authCodeExchange.ts:10,31-87`, POSTing `/v1/auth/token-exchange` and returning an access token. Desktop deep-link protocol and routes are in `main/utils/deepLink.ts:1-5,21-39,157-213`; production scheme is `tiro:` and development scheme is `tiro-dev:`.
2. **Live audio capture and streaming.** `main/services/AudioCaptureProcess.ts:47-57,155-173` models a native audio sidecar with 16 kHz and 48 kHz PCM paths and explicit permission/process failure states. `main/services/StompStreamingService.ts:203-228,257-401` creates a `ws` + `@stomp/stompjs` connection to `${VITE_WS_BASE_URL}/stomp`, authenticates with Bearer token and subscribes to alert/frame/status topics. It publishes `/pub/resume`, `/pub/pause`, `/pub/end`, `/pub/note/summary`, `/pub/recording-file`, `/pub/recording-file-uri` and `/pub/frame` (`StompStreamingService.ts:149-154,700-754`). Disconnected PCM is buffered and replayed (`:748-836`).
3. **Offline recording and recovery.** `main/services/OfflineRecordingPersistence.ts:107-179,245-327` persists sessions/settings in `electron-store`; `main/preload.ts:531-581` exposes start/pause/resume/stop, temp-file, session and upload operations. Upload is signed multipart S3: `main/utils/uploadOfflineRecordingFile.ts:5-8,26-36,67-98` caps files at 1 GiB, uses 32 MiB parts and validates signed HTTPS hosts `theplato-app-tiro-audio-dev.s3-accelerate.amazonaws.com` and `tiro-audio.s3-accelerate.amazonaws.com`. These are endpoint names only; signed URLs/tokens are not recovered here.
4. **Native and OS integration.** The bridge includes microphone/system-audio permission, device switching, pause/stop/gain and diagnostics (`main/preload.ts:649-699`). The native microphone dependency is `@plato-corp/microphone` in `package.json` and preserved under `preserved/app/node_modules`; the source map shows runtime use in `main/index.ts:1457-1465`. Windows/macOS window, tray, menu, notification, overlay and meeting mode are implemented in `main/utils/window.ts` and `main/services/OverlayWindowService.ts`.
5. **Updates, telemetry and integrations.** Update feed/relaunch code is in `main/utils/updateFeed.ts` and `main/index.ts:767-791`; the Windows release feed host is referenced at `main/index.ts:767`. Sentry is initialized at `main/index.ts:262-265`; renderer assets also contain PostHog, Datadog, Featurebase and Channel integrations as package/build strings. Google Drive picker uses a browser web route and returns through `tiro://google-drive/picked` (`main/utils/googleDrivePicker.ts:4-16,49-72`; `main/index.ts:1668-1688`).

## Recovery assessment

The shipped artifact is highly recoverable as a **behavioral rebuild**: sourcemaps restore dozens of meaningful TypeScript modules under `application/src/main`, `application/src/shared` and selected renderer entities/utilities; package metadata preserves dependency versions; preload gives a concrete IPC contract; and the renderer bundle plus CSS/assets preserves the UI and visual resources. A byte-identical original source tree is not recoverable from this package.

The largest gaps are:

- The renderer application source tree is not restored as ordinary files. The 5.8 MB bundled module graph is present, but REA marked `.vite/renderer/main_window/assets/index-CXautzcB.js` resource-constrained; React component names, routes and state boundaries require focused bundle/source-map recovery.
- `index.html` inline startup code was excluded from REA semantic analysis, so its storage and transition behavior is known only from the preserved file.
- Exact build-time environment files, Vite/Forge configuration, workspace packages (`@plato-corp/tiro-core`, `tiro-common`, `tds`), test sources, release signing credentials and native audio build inputs are absent or only represented by compiled dependencies.
- Runtime execution, authentication validity, server schema compatibility, native audio behavior and cloud availability were not tested in this pass. REA reports 4 browser windows, 4 explicit web-preference sets, 1 preload entrypoint, 3 context-bridge APIs, 157 literal IPC channels, 121 paired renderer transmissions, 125 main handlers and 2 sender-validation observations; these are static observations.

## Recommended reconstruction order

Preserve the extracted package as the golden reference. Recreate the workspace/package graph and build-time environment first; then implement the recovered preload/main IPC contract; next recover renderer route/component boundaries from the renderer bundle and its map; finally replace or rebuild native audio and validate auth, live STOMP, offline upload and deep-link flows against controlled test services. Keep all cloud values as configurable environment variables and treat the S3 upload hosts and auth endpoints as external contracts that require server-side confirmation.
